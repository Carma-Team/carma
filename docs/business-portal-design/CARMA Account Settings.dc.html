Basic Account Settings

החשבון שלי — the signed-in user's own details, separate from פרטי העסק (business info) and איש קשר (contact person). Deliberately small: personal fields, a password entry point, and התנתקות. No security history, sessions, 2FA, or notification prefs yet.

Flagged, not built. The password-change flow shown is a form + entry point only — its backend verification behavior (current-password check, re-auth, email confirmation) is undefined; see the box below.
Frames are 1440×900. Out of scope this round: employees, roles/permissions, security history, sessions, 2FA, notification prefs, org settings, analytics.

Proposed structure

החשבון שלי — פריט ניווט קיים («הגדרות»), בלי טאבים נוספים
כרטיס «פרטים אישיים» — שם, דוא״ל, טלפון של המשתמש המחובר בלבד
כרטיס «סיסמה» — כניסה לשינוי סיסמה, לא טופס מלא בעמוד
פעולת התנתקות — ניטרלית, לא באדום
אותו פס שמירה דביק מ«פרטי העסק» — עקביות בין העמודים

Assumptions

Personal details (name, email, phone) belong to this one user only — editing them never touches Business Profile or Contact Person data, even if values happen to match today.
Password change is a separate short modal, not inline fields — keeps the main form's save bar simple and avoids mixing identity-sensitive input with routine edits.
Changing email here is assumed to require the same "unsaved change" save-bar pattern as other fields — no separate confirmation email flow is designed since none was specified.
Logout needs no confirmation dialog — it's reversible (just sign in again) and not a consequential action.
Flagged separately — new requirements noticed, not assumed or built
